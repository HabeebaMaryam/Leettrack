# LeetTrack - LeetCode Progress Tracker

## Overview

LeetTrack is a full-stack web application designed to track and analyze LeetCode programming progress for students and administrators. The platform fetches real-time statistics from LeetCode's GraphQL API and provides comprehensive analytics, rankings, and batch management capabilities. Students can monitor their coding progress through visual dashboards, while administrators can manage users, create batches, and analyze performance metrics across the platform.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture

**Framework & Build Tool**
- React 18+ with TypeScript for type-safe component development
- Vite as the build tool and development server for fast HMR and optimized production builds
- Single-page application (SPA) architecture using Wouter for client-side routing

**State Management & Data Fetching**
- TanStack Query (React Query) for server state management, caching, and automatic refetching
- Context API for global application state (authentication and theme)
- Local component state using React hooks for UI-specific state

**UI Component System**
- Radix UI primitives for accessible, unstyled component foundations
- Shadcn/ui component library configured with the "new-york" style variant
- Tailwind CSS for utility-first styling with custom design tokens
- Custom CSS variables for theming supporting light/dark modes
- Design system inspired by Linear, GitHub, and Vercel for developer-focused UX

**Design Patterns**
- Protected routes using HOC pattern for authentication and role-based access control
- Reusable presentational components (StatCard, EmptyState, charts)
- Custom hooks for shared logic (useAuth, useTheme, useIsMobile)
- Form handling with React Hook Form and Zod for validation

### Backend Architecture

**Server Framework**
- Express.js with TypeScript for the REST API server
- JWT token-based authentication for Replit iframe compatibility
- Middleware pattern for authentication (requireAuth) and authorization (requireAdmin)

**API Design**
- RESTful API endpoints organized by domain (/api/auth, /api/stats, /api/admin)
- JSON request/response format
- JWT tokens sent via Authorization header (Bearer scheme)

**Authentication & Authorization**
- Bcrypt for password hashing with configurable salt rounds
- JWT token-based authentication (migrated from sessions to work in Replit iframe)
- Tokens stored in localStorage on frontend, sent in Authorization header
- Token expiration: 24 hours (configurable)
- Role-based access control with "student" and "admin" user roles
- Admin-only user creation (public registration disabled by design)

**Data Access Layer**
- Storage abstraction pattern with IStorage interface for database operations
- DatabaseStorage implementation using Drizzle ORM
- Separation of concerns between routes, business logic, and data access

### Database Architecture

**Database Technology**
- PostgreSQL as the primary relational database
- Neon serverless PostgreSQL with WebSocket support for efficient connections
- Drizzle ORM for type-safe database queries and schema management

**Schema Design**
- Users table: Stores student and admin accounts with credentials, roles, departments, and LeetCode usernames
- Stats table: Stores LeetCode statistics with foreign key relationship to users (cascade delete)
- Batches table: Manages student groups with many-to-many relationship through junction table
- UUID primary keys generated by PostgreSQL for all tables

**Data Relationships**
- One-to-one: User to Stats (each user has one stats record)
- Many-to-many: Users to Batches through batchStudents junction table
- Foreign key constraints with cascade delete to maintain referential integrity

### External Dependencies

**LeetCode Integration**
- Direct integration with LeetCode's public GraphQL API (https://leetcode.com/graphql)
- Fetches user statistics: total solved, difficulty breakdown, ranking, contest rating
- Retrieves recent submissions with timestamps and status
- No authentication required for public user data
- Custom GraphQL queries defined in server/leetcode.ts

**Third-Party Services**

**Development Tools**

### Key Architectural Decisions

**Monorepo Structure**
- Client, server, and shared code in single repository with path aliases
- Shared schema definitions between frontend and backend for type consistency
- Centralized TypeScript configuration with module path resolution

**JWT Authentication (Migrated from Sessions)**
- JWT token-based authentication implemented to work in Replit's iframe environment
- Browsers block third-party cookies in iframes, breaking session-based auth
- JWT tokens sent in Authorization header bypass cookie restrictions
- Tokens stored in localStorage for persistence across page refreshes
- Stateless authentication reduces database lookups and improves scalability
- Token verification happens on every request via middleware

**Admin-Controlled User Management**
- Public registration disabled to maintain platform control
- Only administrators can create user accounts
- Reduces spam and ensures all users are authorized members

**Real-time Data Fetching**
- LeetCode stats fetched on-demand rather than cached indefinitely
- Manual refresh capability for users to update their statistics
- No background job processing or scheduled data syncing currently implemented

**Responsive Design Approach**
- Mobile-first Tailwind breakpoints with responsive grid layouts
- Sidebar collapses to sheet/drawer on mobile devices
- Separate mobile and desktop navigation patterns using useIsMobile hook
